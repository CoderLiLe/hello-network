## WebSocket

WebSocket 是基于 TCP 的支持全双工通信的应用层协议。
- 2011 年由 IETF 标准化为 RFC 6455
- 客户端和服务器任何一方都可以主动发消息

### 应用场景
- 社交订阅、股票基金报价、体育实况更新
- 多媒体聊天、多玩家游戏

### 与 HTTP 的关系
- WebSocket 和 HTTP 属于平级关系，都是应用层协议
- 使用 80（ws://）和 443（wss://）端口
- WebSocket 需要先建立连接，是一种有状态协议

### 建立连接
WebSocket 借助 HTTP 协议建立连接（握手，Handshake）：
```
GET /chat HTTP/1.1
Host: example.com
Connection: Upgrade
Upgrade: websocket
Sec-WebSocket-Version: 13
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
```

服务器响应：
```
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=
```

### Sec-WebSocket-Key 验证
1. Key 加上固定 GUID：`258EAFA5-E914-47DA-95CA-C5AB0DC85B11`
2. 进行 SHA-1 摘要计算
3. 结果进行 Base64 编码
4. 作为 Sec-WebSocket-Accept 返回

## WebService

WebService 是一种跨编程语言和跨操作系统平台的远程调用技术标准。

### 使用场景
- 天气预报、手机归属地查询、航班信息查询

### 核心概念
| 术语 | 说明 |
|------|------|
| SOAP | 简单对象访问协议，使用 HTTP + XML 封装数据 |
| WSDL | Web 服务描述语言，XML 文档，描述接口细节 |

> 现在很多企业直接使用 Web API（HTTP + JSON）取代 WebService。

## REST

REST（Representational State Transfer）：表现层状态转移，是一种互联网软件架构设计风格。

### 实践建议
- URL 中使用名词（复数形式），不使用动词
  - 推荐：`/users`、`/users/123`
  - 不推荐：`/getUser`、`/createUser`
- 使用 HTTP 方法表达动作
  - GET：查询
  - POST：创建
  - PUT：更新
  - DELETE：删除
- 资源连接使用子资源形式：`/users/123/orders`
- API 版本化：`/v1/users`
- 返回 JSON 格式数据
- 发生错误时返回合适的 HTTP 状态码

## HTTPDNS

HTTPDNS 基于 HTTP 协议向 DNS 服务器发送域名解析请求，替代了基于 DNS 协议的传统方式。

### 优势
| 优势 | 说明 |
|------|------|
| 防劫持 | 绕开运营商，防止 DNS 被污染 |
| 精准调度 | 精确识别来源请求，导向最准确节点 |
| 高可用 | 多地集群容灾，秒级故障切换 |
| 高性能 | 接入节点覆盖国内运营商及海外 |

> 常用在移动互联网中（Android、iOS 开发）。

## FTP (文件传输协议)

FTP（File Transport Protocol），基于 TCP 的应用层协议。RFC 959 定义。

- URL 格式：`ftp://[user[:password]@]host[:port]/url-path`

### 连接模式
FTP 有 2 种连接模式，都需要建立 2 个连接：
1. **控制连接**：传输状态信息（命令）
2. **数据连接**：传输文件和目录信息

#### 主动模式
1. 客户端打开随机命令端口 N，连接服务器命令端口 21
2. 客户端监听 N+1 数据端口，发送 Port 命令
3. 服务器打开 20 号数据端口，连接客户端 N+1 端口

#### 被动模式
1. 客户端命令端口 N 连接服务器命令端口 21
2. 客户端发送 PASV 命令
3. 服务器打开随机数据端口 P，告知客户端
4. 客户端数据端口 N+1 连接服务器数据端口 P

## 邮件协议

### 发邮件
| 协议 | 说明 |
|------|------|
| SMTP | 简单邮件传输协议，基于 TCP，RFC 5321 |
| 默认端口 | 25，SSL/TLS 使用 465 |

### 收邮件
| 协议 | 说明 |
|------|------|
| POP3 | 邮局协议，基于 TCP，RFC 1939，默认端口 110/995 |
| IMAP4 | 因特网信息访问协议，基于 TCP，RFC 3501，默认端口 143/993 |

### POP vs IMAP
| 特性 | POP | IMAP |
|------|-----|------|
| 邮件存储 | 下载到本地，可删除服务器上的 | 保留在服务器 |
| 操作同步 | 客户端操作不同步到服务器 | 客户端操作同步到服务器 |
| 多客户端 | 每个客户端独立，各自有副本 | 所有客户端看到相同的邮件和文件夹 |

## IPv6

IPv6（Internet Protocol version 6）：网际协议第 6 版。

- 主要解决 IPv4 地址枯竭问题
- 128 位地址，支持约 3.4×10³⁸ 个地址
- 按地球人口 70 亿算，每人可分得约 4.86×10²⁸ 个 IPv6 地址

### 地址格式
- 128 bit，每 16 bit 一组，共 8 组
- 以冒号分隔，每组以 4 位十六进制表示
- 示例：`2001:0db8:86a3:08d3:1319:8a2e:0370:7344`

**省略规则：**
- 每组前导的 0 可省略：`2001:db8:2de:0:0:0:0:e13`
- 双冒号 `::` 表示一组或多组连续的 0（只能出现一次）
- `::1` 是本地环回地址

### IPv6 首部
- 40 字节固定首部
- 关键字段：Version (4bit, 0110)、Traffic Class、Payload Length、Hop Limit、Source Address、Destination Address、Flow Label
