## 网络层攻击 - ARP 欺骗

ARP 欺骗（ARP spoofing），又称 ARP 毒化（ARP poisoning）、ARP 病毒、ARP 攻击。

### 造成的影响
- 获取局域网上的数据包，甚至篡改数据包
- 让特定电脑之间无法正常通信
- 将特定 IP 的流量错误地送到攻击者处

### 核心步骤示例
1. 攻击者 C 拥有 A、B 的 IP 和 MAC 地址
2. C 发送 ARP 响应给 B，源 IP 设为 A 的 IP，源 MAC 设为 C 的 MAC
3. B 更新 ARP 表，将 A 的 MAC 改为 C 的 MAC
4. B 发送给 A 的数据包会到达 C
5. C 可以窃听或篡改数据后再转发给 A

### 防护措施
- **静态 ARP**：手动绑定 IP 和 MAC
- **DHCP Snooping**：检测伪造的 ARP 数据包
- **ARP 监控软件**：监听 ARP 的不正常变动

## DoS / DDoS 攻击

### DoS (拒绝服务攻击)
使目标电脑的网络或系统资源耗尽，使服务中断或停止。

### DDoS (分布式拒绝服务攻击)
使用多个被攻陷的电脑作为"僵尸"向特定目标发动 DoS 攻击。

> 2018 年 3 月，GitHub 遭到迄今为止规模最大的 DDoS 攻击。

### DoS 攻击分类
| 类型 | 说明 |
|------|------|
| 带宽消耗型 | UDP 洪水攻击、ICMP 洪水攻击 |
| 资源消耗型 | SYN 洪水攻击、LAND 攻击 |

### 防御方式
- **防火墙**：设置规则拒绝特定协议、端口或 IP
- **交换机**：速度限制和访问控制
- **路由器**：速度限制和访问控制
- **黑洞引导**：将所有攻击流量发送至"黑洞"
- **流量清洗**：区分正常流量和恶意流量

## 传输层攻击

### SYN 洪水攻击
攻击者发送 SYN 请求后，不发送 ACK（第 3 次握手），让目标等待、消耗资源。

**防护**：参考 RFC 4987

### LAND 攻击
持续发送相同源地址和目标地址的欺骗数据包，使目标试图与自己建立连接，消耗系统资源直至崩溃。

**防护**：防火墙拦截、操作系统安全补丁、路由器配置上行与下行筛选器。

## 应用层攻击

### DNS 劫持
攻击者篡改域名的解析结果，使指向该域名的 IP 变成另一个 IP。

**预防**：使用靠谱的 DNS 服务器：
- 114.114.114.114
- 谷歌：8.8.8.8、8.8.4.4
- 微软：4.2.2.1、4.2.2.2
- 阿里：223.5.5.5、223.6.6.6

### HTTP 劫持
对 HTTP 数据包进行拦截处理，比如插入 JS 代码（如访问某些网站时出现弹窗广告）。

## 加密技术

### 加密方式分类

#### 1. 不可逆加密 - 单向散列函数
- MD5、SHA 等
- 根据消息内容计算出固定长度的散列值
- 具备**单向性**，无法从散列值还原原始消息

**特点：**
- 任意长度消息 → 固定长度散列值
- 计算速度快
- 消息不同，散列值也不同

**应用：**
- 防止数据被篡改
- 密码加密存储

#### 2. 可逆加密

##### 对称加密
加密和解密使用**同一个密钥**。

| 算法 | 说明 |
|------|------|
| DES | 已可在短时间内破解，不建议使用 |
| 3DES | 三重 DES，仍被银行使用，但逐渐暴露出问题 |
| AES | 取代 DES 成为新标准，密钥长度有 128/192/256 三种 |

**密钥配送问题**：如何安全地将密钥发送给接收方？

##### 非对称加密
加密和解密使用不同的密钥：
- **公钥**：公开的加密密钥
- **私钥**：由接收者自己保管，不能公开

**RSA**：目前使用最广泛的非对称加密算法

**解决密钥配送问题：**
1. 接收者生成一对公钥和私钥
2. 将公钥发给发送者
3. 发送者使用公钥加密消息
4. 接收者使用私钥解密

#### 3. 混合密码系统

结合对称加密和非对称加密的优势：
- 使用**会话密钥**（对称加密）加密消息 → 速度快
- 使用**公钥**（非对称加密）加密会话密钥 → 解决密钥配送

**加密过程：**
1. 接收者生成密钥对，将公钥共享给发送者
2. 发送者随机生成一个会话密钥
3. 用会话密钥加密消息（对称加密）
4. 用接收者的公钥加密会话密钥（非对称加密）
5. 将加密的消息和加密的会话密钥一并发送

**解密过程：**
1. 接收者用私钥解密会话密钥
2. 用会话密钥解密消息

## 数字签名

### 作用
- 确认消息的完整性
- 识别消息是否被篡改
- 防止消息发送人否认

### 原理
| 角色 | 非对称加密 | 数字签名 |
|------|-----------|----------|
| 发送者加密时使用 | 公钥 | 私钥（签名） |
| 接收者解密时使用 | 私钥 | 公钥（验签） |

> 数字签名是将非对称加密反过来使用。私钥负责签名，公钥负责验签。

## 证书 (Certificate)

公钥证书（Public-key Certificate，PKC）：
- 包含姓名、邮箱等个人信息以及此人的公钥
- 由认证机构（CA）施加数字签名
- 各大 CA 的公钥默认已内置在浏览器和操作系统中
