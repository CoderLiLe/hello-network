# 传输层

> 讲师: 李明杰 (小码哥教育)

## TCP vs UDP

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接性 | 面向连接 | 无连接 |
| 可靠性 | 可靠传输，不丢包 | 不可靠传输，可能丢包 |
| 首部占用空间 | 大（至少 20 字节） | 小（8 字节） |
| 传输速率 | 慢 | 快 |
| 资源消耗 | 大 | 小 |
| 应用场景 | 浏览器、文件传输、邮件 | 音视频通话、直播 |
| 应用层协议 | HTTP、FTP、SMTP | DNS、DHCP |

## UDP 数据格式

UDP 是无连接的，减少了建立和释放连接的开销。UDP 尽最大能力交付，不保证可靠交付。

### UDP 首部 (8 字节)
- **源端口** (2 字节)
- **目的端口** (2 字节)
- **UDP 长度** (2 字节)：首部长度 + 数据长度
- **检验和** (2 字节)：计算内容为伪首部 + 首部 + 数据

## TCP 数据格式

### TCP 首部 (至少 20 字节)

#### 数据偏移 (4 位)
- 取值范围 `0x0101 ~ 0x1111`，乘以 4 为首部长度
- 首部长度范围：20~60 字节

#### 标志位 (Flags)
| 标志 | 名称 | 说明 |
|------|------|------|
| URG | Urgent | 紧急指针字段有效 |
| ACK | Acknowledgment | 确认号字段有效 |
| PSH | Push | 推送数据 |
| RST | Reset | 连接出现严重差错，强制关闭 |
| SYN | Synchronization | 建立连接请求 |
| FIN | Finish | 释放连接 |

#### 序号、确认号、窗口
- **序号** (4 字节)：每个字节都有编号，序号是数据部分第一个字节的编号
- **确认号** (4 字节)：期望对方下一次发送的数据的第一个字节的编号
- **窗口** (2 字节)：流量控制，告知对方允许发送的数据大小

## TCP 可靠传输

### 停止等待协议 (ARQ)
ARQ（Automatic Repeat-reQuest）：自动重传请求。发送方发送数据后启动定时器，超时未收到确认则重传。

### 连续 ARQ 协议 - 滑动窗口
如果接收窗口最多能接收 4 个包，但发送方只发了 2 个包，接收方等待一定时间后没有第 3 个包，就会返回确认。

### SACK (选择性确认)
当中间某个数据包丢失时，TCP 会重传最后一个确认后的所有分组，这降低了性能。SACK 告诉发送方哪些数据丢失、哪些已收到，使 TCP 只重新发送丢失的包。

**为什么在传输层分段，而不是在网络层？**
- 可靠传输在传输层控制
- 传输层不分段 → 数据丢失需重传整个传输层数据
- 传输层分段 → 只需重传丢失的段

## TCP 流量控制

当接收方缓存满时，发送方继续发送会导致大量丢包。流量控制让发送方的发送速率不要太快，让接收方来得及接收处理。

### 原理
- 通过确认报文中的**窗口字段**控制发送速率
- 发送窗口 ≤ 接收方给出的窗口大小
- 当收到 0 窗口通知时，发送方停止发送，开启定时器，定期询问最新窗口大小

## TCP 拥塞控制

拥塞控制防止过多数据注入网络，避免路由器或链路过载。与流量控制不同，拥塞控制是全局性的过程，涉及所有主机和路由器。

### 方法
1. **慢开始 (Slow Start)**：cwnd 从较小值开始，每收到一个 ACK 就成倍增长（指数级）
2. **拥塞避免 (Congestion Avoidance)**：达到 ssthresh 后线性增长
3. **快重传 (Fast Retransmit)**：连续收到 3 个重复确认就立即重传
4. **快恢复 (Fast Recovery)**：将 ssthresh 减为峰值一半，cwnd 设为新 ssthresh

### 关键变量
- **MSS**：每个段最大的数据部分大小
- **cwnd**：拥塞窗口
- **rwnd**：接收窗口
- **swnd**：发送窗口 = min(cwnd, rwnd)

## TCP 连接管理

### 3 次握手 (建立连接)

```
客户端                         服务器
  |      SYN=1, seq=x           |
  | ─────────────────────────>  | LISTEN
  |    SYN=1, ACK=1, seq=y,    |
  |          ack=x+1            |
  | <─────────────────────────  | SYN-RCVD
  |    ACK=1, seq=x+1,         |
  |          ack=y+1            |
  | ─────────────────────────>  | ESTABLISHED
  |                             |
```

#### 为什么需要 3 次握手？
防止 server 端一直等待，浪费资源。如果只有 2 次握手，过期的连接请求可能导致 server 误以为建立了新连接。

#### 第 3 次握手失败怎么办？
server 会重新发送 SYN+ACK 包，多次重试后发送 RST 包强制关闭连接。

### 4 次挥手 (释放连接)

```
客户端                         服务器
  |      FIN=1, seq=u          |
  | ─────────────────────────>  | CLOSE-WAIT
  |      ACK=1, seq=v,         |
  |          ack=u+1            |
  | <─────────────────────────  |
  |      FIN=1, ACK=1,         |
  |          seq=w, ack=u+1     |
  | <─────────────────────────  | LAST-ACK
  |      ACK=1, seq=u+1,       |
  |          ack=w+1            |
  | ─────────────────────────>  | CLOSED
  |                              |
```

#### 为什么需要 4 次挥手？
TCP 是全双工模式。第 1 次挥手表示主机 1 没有数据要发送了；第 2 次挥手表示主机 2 已知道；第 3 次挥手表示主机 2 也没有数据要发送了；第 4 次挥手确认关闭。

#### TIME-WAIT 状态
- 客户端发送 ACK 后需要等待 2MSL 再真正关闭
- MSL（Maximum Segment Lifetime）：TCP 报文在 Internet 上的最长生存时间
- RFC 1122 建议 MSL 为 2 分钟
- 防止本次连接的数据包误传到下一次连接

## 端口 (Port)

- UDP 和 TCP 首部中端口占用 2 字节（0~65535）
- 客户端源端口是临时开启的随机端口
- 防火墙可以设置开启/关闭某些端口提高安全性

### 常用命令
| 命令 | 说明 |
|------|------|
| `netstat -an` | 查看被占用的端口 |
| `netstat -anb` | 查看占用端口的应用程序 |
| `telnet 主机 端口` | 测试是否可以访问某端口 |
