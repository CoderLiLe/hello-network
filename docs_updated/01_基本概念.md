## 互联网与网络协议

互联网的出现彻底改变了人们的生活方式，足不出户就可以购物、聊天、看电影、买车票、上班等。

**核心问题：数据是如何从一个设备传递到另一个设备的？**
- 这一切都是由**网络协议**来规定的。没有网络协议，就没有今天的互联网。

### 为什么要学习网络协议？
- 互联网、移动互联网、物联网，都离不开网络协议
- 最熟悉的网络协议：HTTP
- 为了满足各种需求，有各式各样的网络协议（HTTPS、SMTP、MQTT、RTMP 等）

## 网络互连模型

### OSI 参考模型（7 层）
| 层号 | 名称 | 说明 |
|------|------|------|
| 7 | 应用层 (Application) | 用户接口 |
| 6 | 表示层 (Presentation) | 数据格式转换 |
| 5 | 会话层 (Session) | 会话管理 |
| 4 | 运输层 (Transport) | 端到端传输 |
| 3 | 网络层 (Network) | 路由选择 |
| 2 | 数据链路层 (Data Link) | 帧传输 |
| 1 | 物理层 (Physical) | 比特流传输 |

### TCP/IP 协议（4 层）
| 层号 | 名称 | 说明 |
|------|------|------|
| 4 | 应用层 (Application) | HTTP、FTP、SMTP 等 |
| 3 | 运输层 (Transport) | TCP、UDP |
| 2 | 网际层 (Internet) | IP |
| 1 | 网络接口层 (Network Access) | 物理网络 |

### 实用模型（5 层）
学习中常用的 5 层模型：
1. **物理层** - 比特流（Bits）
2. **数据链路层** - 帧（Frames），MAC 地址
3. **网络层** - 包（Packet），IP 地址
4. **运输层** - 段（Segments），TCP/UDP
5. **应用层** - 报文（Message），HTTP、FTP、SMTP、DNS、DHCP

## 数据请求过程

```
客户端 → [应用层 → 运输层 → 网络层 → 数据链路层 → 物理层]
                                                    ↓
服务器 ← [应用层 ← 运输层 ← 网络层 ← 数据链路层 ← 物理层]
```

数据从客户端应用层逐层向下封装，经过网络传输，到达服务器后逐层向上解封装。

## 计算机之间的连接方式

### 网线直连
- 需要使用交叉线（不是直通线）

### 同轴电缆
- 半双工通信
- 容易冲突
- 不安全
- 中间断则全网瘫痪

### 集线器 (Hub)
- 半双工通信
- 容易冲突
- 不安全
- 不具备智能

### 网桥 (Bridge)
- 能通过自学习得知每个接口侧的 MAC 地址
- 起到隔绝冲突域的作用

### 交换机 (Switch)
- 相当于接口更多的网桥
- 全双工通信
- 比集线器安全

### 路由器 (Router)
- 可以在不同网段之间转发数据
- 隔绝广播域
- 前面几种设备连接的设备必须在同一网段
