TCP 三次握手 (交互演示)

点击"下一步"逐步观察三次握手和四次挥手的过程：

步骤 0/7
0 初始 CLOSED → SYN-SENT 客户端主动打开, 发送 SYN
1 C → S SYN=1, seq=x 客户端发送连接请求, 进入 SYN-SENT 状态
2 S → C SYN=1, ACK=1, seq=y, ack=x+1 服务器回复 SYN+ACK, 进入 SYN-RCVD 状态
3 C → S ACK=1, seq=x+1, ack=y+1 客户端确认, 进入 ESTABLISHED; 服务器收到后也进入 ESTABLISHED
4 数据传输 [ 应用数据 ] 双向数据传输
5 C → S FIN=1, seq=u 客户端发送 FIN, 进入 FIN-WAIT-1
6 S → C ACK=1, seq=v, ack=u+1 服务器回复 ACK, 进入 CLOSE-WAIT; 客户端进入 FIN-WAIT-2
7 S → C FIN=1, ACK=1, seq=w, ack=u+1 服务器发送 FIN, 进入 LAST-ACK
8 C → S ACK=1, seq=u+1, ack=w+1 客户端确认, 等待 2MSL 后关闭; 服务器立即关闭

TCP vs UDP

TCP 面向连接

  • ✅ 可靠传输
  • ✅ 保证顺序
  • ✅ 流量控制
  • ✅ 拥塞控制
  • ❌ 速度较慢
  • ❌ 首部大 (20+ 字节)
  • 📌 浏览器、文件传输、邮件

UDP 无连接

  • ❌ 不可靠传输
  • ❌ 不保证顺序
  • ❌ 无流量控制
  • ❌ 无拥塞控制
  • ✅ 速度快
  • ✅ 首部小 (8 字节)
  • 📌 音视频通话、直播

HTTP 报文格式

请求报文 (Request)

GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html
Cookie: session=abc123
                              ← 空行
(请求体 - GET 通常为空)

响应报文 (Response)

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234
Set-Cookie: session=abc123
Server: Apache
                              ← 空行
<!DOCTYPE html>
<html>...</html>

502 Bad Gateway (网关错误)
503 Service Unavailable (服务不可用)

数据封装与解封装 (交互演示)

点击各层查看数据经过每一层时添加的协议头部：

7 应用层 HTTP 请求头 + 请求体 (JSON/HTML)
4 传输层 TCP 头 (源端口:xxxx, 目的端口:80, seq, ack, flags)
3 网络层 IP 头 (源IP:192.168.x.x, 目的IP:93.184.x.x, TTL, 协议=TCP)
2 数据链路层 MAC 帧 (源MAC, 目的MAC, 类型=0x0800, FCS)
1 物理层 比特流: 10110110 01010110 11100010 ...

发送方: 数据从上层到下层层层添加头部 (封装)
接收方: 数据从下层到上层层层去除头部 (解封装)

DNS 域名解析

用户在浏览器输入 www.example.com 时：

1. 浏览器查询本地 DNS 缓存
2. 本地缓存未命中 → 查询配置的 DNS 服务器
3. DNS 服务器查询根域名服务器 → .com 服务器 → example.com 服务器
4. 返回 IP 地址: 93.184.216.34
5. 浏览器向该 IP 发起 HTTP 请求

常用 DNS 服务器：

  • 🟢 114DNS: 114.114.114.114
  • 🔵 Google: 8.8.8.8
  • 🟡 阿里: 223.5.5.5

加密技术

对称加密

加密和解密使用同一个密钥。

算法: DES (已淘汰), 3DES, AES (推荐)

⚠️ 存在密钥配送问题

非对称加密

使用公钥加密、私钥解密。

算法: RSA (最广泛)

✅ 解决密钥配送问题

❌ 速度较慢

混合密码系统

结合对称和非对称加密的优势：

  1. 用对称密钥加密消息（速度快）
  2. 用公钥加密对称密钥（解决配送）

📌 HTTPS 使用的就是这种方式

云原生网络

VPC (虚拟私有网络)

在云上创建隔离的虚拟网络。不同用户的 VPC 通过 VXLAN 隔离。

💡 每个 VPC 分配一个 VXLAN ID，二层完全不通

容器网络

两主流的容器网络方案：

  • Flannel：Overlay 网络，VXLAN 封装
  • Calico：纯三层网络，BGP 路由

SDN (软件定义网络)

将网络控制面和数据面分离。

📌 OpenFlow 协议、OVS (Open vSwitch)

快速诊断流程

网页打不开？
  1. ping 域名 → DNS 解析正常？
  2. ping IP → 网络层正常？
  3. telnet IP 80 → TCP 端口开放？
  4. curl -v http://IP → HTTP 正常？
