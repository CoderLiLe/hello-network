TCP 三次握手 / 四次挥手

三次握手 (建立连接)

客户端                                   服务器
  |      SYN=1, seq=x                    |  LISTEN
  | ────────── SYN ───────────────>      |
  |   SYN=1, ACK=1, seq=y, ack=x+1      |
  | <────────── SYN+ACK ────────────     |  SYN-RCVD
  |   ACK=1, seq=x+1, ack=y+1           |
  | ────────── ACK ───────────────>      |  ESTABLISHED
  |                                      |
  | ←--------- 数据传输开始 ---------→   |

为什么需要 3 次握手？ 防止 server 端一直等待。如果只有 2 次握手，过期的连接请求可能导致 server 误以为建立了新连接，浪费资源。

四次挥手 (释放连接)

客户端                                   服务器
  |      FIN=1, seq=u                    |  ESTABLISHED
  | ────────── FIN ───────────────>      |  CLOSE-WAIT
  |      ACK=1, seq=v, ack=u+1          |
  | <────────── ACK ────────────────     |
  |      FIN=1, ACK=1, seq=w, ack=u+1   |  LAST-ACK
  | <────────── FIN ────────────────     |
  |      ACK=1, seq=u+1, ack=w+1        |
  | ────────── ACK ───────────────>      |  CLOSED
  |                                      |
  | ←--- 等待 2MSL 后关闭 ---→           |

为什么需要 4 次挥手？ TCP 是全双工模式，双方都需要独立关闭连接。第 1、2 次表示客户端不再发送数据，第 3、4 次表示服务器也不再发送数据。

TCP vs UDP

TCP 面向连接

  • ✅ 可靠传输
  • ✅ 保证顺序
  • ✅ 流量控制
  • ✅ 拥塞控制
  • ❌ 速度较慢
  • ❌ 首部大 (20+ 字节)
  • 📌 浏览器、文件传输、邮件

UDP 无连接

  • ❌ 不可靠传输
  • ❌ 不保证顺序
  • ❌ 无流量控制
  • ❌ 无拥塞控制
  • ✅ 速度快
  • ✅ 首部小 (8 字节)
  • 📌 音视频通话、直播

HTTP 报文格式

请求报文 (Request)

GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html
Cookie: session=abc123
                              ← 空行
(请求体 - GET 通常为空)

响应报文 (Response)

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234
Set-Cookie: session=abc123
Server: Apache
                              ← 空行
<!DOCTYPE html>
<html>...</html>

常见状态码

200 OK (成功)
302 Found (重定向)
304 Not Modified (使用缓存)
400 Bad Request (语法错误)
401 Unauthorized (未认证)
403 Forbidden (拒绝访问)
404 Not Found (未找到)
500 Internal Server Error (服务器错误)
502 Bad Gateway (网关错误)
503 Service Unavailable (服务不可用)

DNS 域名解析

用户在浏览器输入 www.example.com 时：

1. 浏览器查询本地 DNS 缓存
2. 本地缓存未命中 → 查询配置的 DNS 服务器
3. DNS 服务器查询根域名服务器 → .com 服务器 → example.com 服务器
4. 返回 IP 地址: 93.184.216.34
5. 浏览器向该 IP 发起 HTTP 请求

常用 DNS 服务器：

  • 🟢 114DNS: 114.114.114.114
  • 🔵 Google: 8.8.8.8
  • 🟡 阿里: 223.5.5.5

加密技术

对称加密

加密和解密使用同一个密钥。

算法: DES (已淘汰), 3DES, AES (推荐)

⚠️ 存在密钥配送问题

非对称加密

使用公钥加密、私钥解密。

算法: RSA (最广泛)

✅ 解决密钥配送问题

❌ 速度较慢

混合密码系统

结合对称和非对称加密的优势：

  1. 用对称密钥加密消息（速度快）
  2. 用公钥加密对称密钥（解决配送）

📌 HTTPS 使用的就是这种方式
