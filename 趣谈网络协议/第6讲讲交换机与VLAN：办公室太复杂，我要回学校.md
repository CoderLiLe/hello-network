# 第6讲讲交换机与VLAN：办公室太复杂，我要回学校

## 拓扑结构

两台交换机的情形：两台交换机连接着三个局域网，每个局域网上都有多台机器。如果机器1只知道机器4的IP地址，当它想要访问机器4，把包发出去的时候，它必须要知道机器4的MAC地址。

于是机器1发起广播，机器2收到这个广播，但目标不是它，直接忽略。交换机A一开始是不知道任何拓扑信息的，在它收到这个广播后，采取的策略是，除了广播包来的方向外，它还要转发给其他所有的网口。于是机器3也收到广播信息了，同样忽略。
交换机 B 同样收到广播并转发到局域网三。机器4和机器5都收到了广播信息。机器4主动响应说，这是找我的，这是我的MAC地址。于是一个ARP请求就成功完成了。
通过这个过程，交换机 A 和 B 学习到：机器1是在左边这个网口的。当机器2要访问机器1的时候，机器2并不知道机器1的MAC地址，所以机器2会发起一个ARP请求。这个广播消息会到达机器1，也同时会到达交换机A。交换机A已经知道机器1是不可能在右边的网口的，所以这个广播信息就不会广播到局域网二和局域网三。
当机器3要访问机器1的时候，也需要发起一个广播的ARP请求。交换机A和交换机B都能够收到这个广播请求。交换机 A 知道机器 1 在左侧网口，所以会把广播消息转发到局域网一。同时，交换机B收到这个广播消息之后，由于它知道机器1是不在右边这个网口的，所以不会将消息广播到局域网三。
## 环路问题
两台交换机同时连接两个局域网时会形成环路：

一开始，机器1并不知道机器2的MAC地址，所以它需要发起一个ARP的广播。广播到达机器2，机器2会把MAC地址返回来，
这两个交换机还是都能够收到广播包的。交换机A一开始是不知道机器2在哪个局域网的，所以它会把广播消息放到局域网二，在局域网二广播的时候，交换机B右边这个网口也是能够收到广播消息的。交换机B会将这个广播息信息发送到局域网一。局域网一的这个广播消息，又会到达交换机A左边的这个接口。交换机A还是不知道机器2在哪个局域网，于是将广播包又转发到局域网二。形成广播风暴环路。
但实际上：机器1的广播包到达交换机A和交换机B的时候，本来两个交换机都学会了机器1是在局域网一的，但是当交换机A将包广播到局域网二之后，交换机B右边的网口收到了来自交换机A的广播包。根据学习机制，交换机 B 收到来自交换机 A 的广播包后，错误地学习到机器 1 在右侧网口，覆盖了之前的正确记录。交换机 A 同样会错误学习。
广播包在环路中不断循环，交换机的 MAC 地址表反复被错误更新。
广播包在环路中不断复制增殖，最终导致广播风暴，网络瘫痪。必须解决环路问题。
## STP 协议概念

STP（Spanning Tree Protocol）将有环的图破环生成树，消除环路。

核心概念：

- **Root Bridge（根交换机）**：生成树的根节点，优先级最高的交换机
- **Designated Bridge（指定交换机）**：每个网段中到根桥开销最小的交换机，负责转发该网段的数据
- **BPDU（网桥协议数据单元）**：STP 的控制报文，用于交换机之间交换拓扑信息，只有根桥可以发起

- **Priority Vector（优先级向量）**：比较顺序为 [Root Bridge ID, Root Path Cost, Bridge ID, Port ID]，值越小越优先。

## STP 工作过程

初始时所有交换机都认为自己是根桥，互相发送 BPDU 比较优先级。合并过程有四种情形：

- **情形一：根桥相遇** — 优先级高的胜出，低的归顺
- **情形二：同属一个根桥的交换机相遇（环路检测）** — 比较 Root Path Cost，选择到根桥开销更小的路径，阻塞开销大的端口
- **情形三：根桥与其他交换机相遇** — 比较 Root Bridge ID，低的胜出
- **情形四：不同根桥的非根交换机相遇** — 比较所属 Root Bridge ID，低的胜出

最终生成一棵无环的生成树。
## 广播与安全问题
广播域过大会导致性能下降和安全问题（敏感数据被监听）。隔离方式有两种：

- **物理隔离**：每个部门独立交换机+子网，但不灵活，端口利用率低
- **虚拟隔离（VLAN）**：使用VLAN，一个交换机上会连属于多个局域网的机器，

VLAN 在二层帧头中添加 12 位 VLAN ID，支持 4096 个 VLAN。大规模云环境下 4096 个不够用，后续章节会介绍解决方案。
交换机支持 VLAN 后，识别二层的 VLAN ID，只有相同 VLAN 的包才会转发。可以设置每个端口所属 VLAN，且端口所属 VLAN 可随时重新配置。
交换机之间通过 **Trunk 口** 连接，Trunk 口可以转发所有 VLAN 的包。
