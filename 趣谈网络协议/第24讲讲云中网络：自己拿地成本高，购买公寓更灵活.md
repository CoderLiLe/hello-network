# 第24讲 云中网络

## 虚拟化

物理机维护四大问题：采购周期长、扩容麻烦、规格不匹配、复用具冲突。**qemu-kvm** 在一台物理机中创建多台虚拟机，灵活指定 CPU/内存/硬盘/网卡规格。

虚拟化软件像一个"骗子"：向上骗虚拟机里的应用让它们感觉独享资源，实际全部共享物理机资源。

## 虚拟网卡（TUN/TAP）

qemu-kvm 打开 TUN/TAP 字符设备，物理机上出现一张虚拟 TAP 网卡。发包流程：

```
VM内应用 → qemu-kvm 将包转为文件流 → 写字符设备 → 内核 TUN/TAP 驱动还原包 → TCP/IP协议栈 → 虚拟TAP网卡发出
```

## 云中网络四大需求

- **共享**：多虚拟机共享有限物理网卡出口
- **隔离**：数据不能互窃听，流量不能互相影响
- **互通**：同物理机/跨物理机的同用户虚拟机互通
- **灵活**：虚拟机频繁创建/删除/迁移，网络配置需跟上

## 共享与互通方案

### 桥接（Bridge）

brctl 创建虚拟网桥 br0，虚拟机的虚拟网卡和物理网卡都连到 br0，同一网段即可互通。所有物理机的 br0 通过物理交换机连接，形成大二层网络。缺点：广播问题严重，仅适合小规模。

### NAT

虚拟机使用独立私网段，网关地址配到 br0 上，通过 `iptables -t nat -A POSTROUTING -o ethX -j MASQUERADE` 做 NAT，物理机充当路由器。

## 隔离方案（VLAN）

- 同一网桥上不同 tag 的虚拟机不互通
- 跨物理机：用 vconfig 创建带 VLAN 的虚拟网卡，不同用户分不同 VLAN
- **局限**：VLAN ID 仅 4096 个，大规模云平台不够用；配置不够灵活；流量隔离未实现

后续 VXLAN、GRE 等 Overlay 方案解决这些局限。
