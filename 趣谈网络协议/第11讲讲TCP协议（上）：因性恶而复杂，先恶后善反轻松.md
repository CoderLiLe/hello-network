# 第11讲 TCP协议

TCP 是面向连接的、可靠的传输层协议，假设网络恶劣（丢包、乱序、拥塞），通过算法保证可靠性。

包头：源/目标端口 + 序列号 + 确认号 + 状态位 + 窗口大小 + 校验和 + 紧急指针。核心：**顺序、丢包、连接维护、流量控制、拥塞控制。**

## 三次握手

```
客户端                       服务端
  |-------- SYN -------------->|  SYN-SENT
  |<---- SYN+ACK --------------|  SYN-RCVD
  |-------- ACK -------------->|  ESTABLISHED
```

两次无法防止失效连接请求到达服务端导致误建连接，三次确保双方消息有去有回。同时协商 ISN（基于时钟递增 + Hash，防猜测）。

## 四次挥手

```
客户端                       服务端
  |-------- FIN -------------->|  FIN-WAIT-1
  |<------- ACK ---------------|  CLOSE-WAIT
  |<------- FIN ---------------|  LAST-ACK
  |-------- ACK -------------->|  TIME-WAIT(2MSL)
```

全双工，一方关闭只表示不再发数据，对方可能还有数据要发，故需四次。TIME-WAIT 等 2MSL 确保最后 ACK 到达、旧连接包消失。

TIME-WAIT 过多：大量短连接。解决：tcp_tw_reuse、长连接、SO_LINGER。

状态链：CLOSED → LISTEN → SYN-SENT/SYN-RCVD → ESTABLISHED → FIN-WAIT-1/CLOSE-WAIT → FIN-WAIT-2 → LAST-ACK → TIME-WAIT → CLOSED

## 可靠传输

- **累计确认**：确认号表示该号之前所有字节已收
- **序列号**：每个包有序号，发送缓存分四个区（已确认/已发未确认/待发/暂不发）
- **自适应重传**：RTT 采样加权平均计算超时，超时后间隔加倍
- **快速重传**：收到 3 个重复 ACK 立即重传；SACK 精确告知哪些包已收/丢失

## 流量控制

接收方 ACK 携带窗口大小，发送窗口 ≤ 此值。窗口为 0 暂停发送，定时发探测包。防低能窗口综合征：窗口太小不更新，等缓冲区半空才通知。

## 拥塞控制

`已发送未确认 <= min(cwnd, rwnd)`，通道容量 = BDP（带宽×延迟）。

| 机制 | 行为 |
|------|------|
| 慢启动 | cwnd 指数增长至 ssthresh |
| 拥塞避免 | 超 ssthresh 后线性增长 |
| 快速恢复 | 3 个重复 ACK → cwnd 减半 → 线性增长 |
| 超时重传 | cwnd=1，重新慢启动 |

BBR 算法：丢包 ≠ 通道满，缓存满才降速已晚。通过探测找到高带宽、低时延平衡点。
