# 第10讲 TCP协议

TCP是面向连接的、可靠的传输层协议，假设网络环境恶劣（丢包、乱序、拥塞），通过算法保证可靠性。

## TCP 包头

源端口 + 目标端口 + 序列号 + 确认号 + 状态位（SYN/ACK/RST/FIN）+ 窗口大小 + 校验和 + 紧急指针。

五个核心问题：**顺序、丢包、连接维护、流量控制、拥塞控制。**

## 三次握手

```
客户端                       服务端
  |-------- SYN -------------->|  CLOSED → SYN-SENT
  |<---- SYN+ACK --------------|  LISTEN → SYN-RCVD
  |-------- ACK -------------->|  ESTABLISHED
```

**为什么三次？** 两次无法防止已失效的连接请求到达服务端导致错误建立连接。三次确保双方的消息都有去有回。

三次握手同时协商起始序列号（ISN），ISN 基于时钟每 4ms 递增 + Hash 算法随机生成，防止不同连接的包混淆和被攻击者猜测。

## 四次挥手

```
客户端                       服务端
  |-------- FIN -------------->|  FIN-WAIT-1
  |<------- ACK ---------------|  CLOSE-WAIT
  |                        (服务端可能还有数据要发)
  |<------- FIN ---------------|  LAST-ACK
  |-------- ACK -------------->|  TIME-WAIT (等2MSL)
```

**为什么四次？** TCP 全双工，一方关闭只表示自己不再发数据，对方可能还有数据要发。

**TIME-WAIT 为什么等 2MSL？** 确保最后的 ACK 能到达对端；让旧连接的包在网络中消失，避免与新连接混淆。

**TIME-WAIT 过多**：大量短连接导致。解决：开启 tcp_tw_reuse、使用长连接、SO_LINGER 强制 RST 关闭。

## TCP 状态机

结合三次握手和四次挥手的状态变迁：

- 加粗实线：客户端状态变迁
- 加粗虚线：服务端状态变迁

关键状态：CLOSED → LISTEN → SYN-SENT / SYN-RCVD → ESTABLISHED → FIN-WAIT-1 / CLOSE-WAIT → FIN-WAIT-2 → LAST-ACK → TIME-WAIT → CLOSED

## 可靠传输机制

### 累计确认

接收方返回确认号表示该序列号之前的所有字节都已收到，无需逐个确认。

### 序列号与重传

- 每个包有序号，发送方缓存按序排列：已确认 / 已发送未确认 / 待发送 / 暂不发送
- 接收方窗口：AdvertisedWindow = MaxRcvBuffer - 已接收未读取

### 自适应重传

超时时间通过采样 RTT 并加权平均动态计算。每次超时重传后，超时间隔加倍（网络差则降低发送频率）。

### 快速重传

收到 3 个重复 ACK 时，不等超时立即重传丢失的包。SACK（选择性确认）可以精确告知哪些包已收到、哪些丢失。

## 流量控制

接收方在 ACK 中携带窗口大小，发送方的发送窗口不能超过此值。窗口为 0 时停止发送，定时发送窗口探测包。防止低能窗口综合征：窗口太小时不更新，等缓冲区一半为空才通知。

## 拥塞控制

通过拥塞窗口 cwnd 控制：`已发送未确认 <= min(cwnd, rwnd)`

通道容量 = 带宽 × 往返延迟，目标是在不丢包的前提下填满管道。

### 四种机制

1. **慢启动**：cwnd 初始很小，每收到 ACK 指数增长，直到 ssthresh
2. **拥塞避免**：超过 ssthresh 后线性增长
3. **快速重传与恢复**：收到 3 个重复 ACK → cwnd 减半 → 线性增长（不重回慢启动）
4. **超时重传**：回到解放前，cwnd=1，重新慢启动

### BBR 算法

传统拥塞控制问题：丢包不等于通道满了（公网丢包）；等到缓存填满才降速已经晚了。BBR 通过不断探测找到高带宽、低时延的平衡点。
