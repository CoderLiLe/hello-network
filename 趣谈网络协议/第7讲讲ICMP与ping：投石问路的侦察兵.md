# 第7讲 ICMP与ping

ICMP（Internet Control Message Protocol，互联网控制报文协议）封装在 IP 包内，用于传递网络控制信息。

## 查询报文类型

**主动请求**，如 ping：

- **ICMP ECHO REQUEST（类型 8）**：主动请求包，包含标识符、序号、发送时间戳
- **ICMP ECHO REPLY（类型 0）**：主动应答包

### ping 的工作过程

```
主机A（192.168.1.1）ping 主机B（192.168.1.2）：

1. A构造ICMP请求包（类型=8，序号+1，记录发送时间）
2. A的IP层封装，加上源/目标IP
3. 检查ARP缓存，获取B的MAC地址（没有则先ARP请求）
4. MAC层封装，发帧
5. B收到帧 → 校验MAC → 提取IP包 → 提取ICMP包
6. B构造ICMP应答包（类型=0，相同序号），发回A
7. A收到应答，用当前时间减去发送时间 = RTT延迟
```

超时未收到应答 → 目标不可达。

**排障建议**：按网络拓扑逐跳 ping，用 `tcpdump -i eth0 icmp` 抓包确认包到达了哪个节点。

## 差错报文类型

**异常触发**，报告网络故障：

| 类型 | 代码 | 含义 |
|------|------|------|
| 终点不可达（3） | 0-4 | 网络/主机/协议/端口不可达，或需分片但禁止 |
| 源抑制（4） | - | 通知源端降低发送速率 |
| 时间超时（11） | - | TTL 耗尽，包被丢弃 |
| 重定向（5） | - | 告知更优路由路径 |

差错报文会在 ICMP 头部后附上出错包的 **IP头 + 正文前8字节**，帮助定位问题源。

## Traceroute：故意制造错误

### 追踪路径

发送 UDP 包，TTL 从 1 开始递增。每经过一个路由器 TTL 减 1，TTL=0 时路由器返回"时间超时"ICMP 包，从而逐跳获取路由器 IP。

### 确定路径 MTU

发送不分片标志的包，长度等于出口 MTU。遇到窄链路时返回"需分片但禁止分片"，逐步减小包长直至到达。

### 确认到达目标

使用一个不可能的值作为 UDP 端口号（>30000），目标主机收到后返回"端口不可达"ICMP 包，从而确认包已到达。
