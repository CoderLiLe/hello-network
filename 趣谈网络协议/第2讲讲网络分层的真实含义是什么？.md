# 第2讲 网络分层的真实含义

## 为什么要分层

复杂程序都要分层，网络协议也不例外。想象网络包是一块有格式的 Buffer，你是一个网络包处理程序——从某个口收包、程序处理、从另一个口发出。

分层的好处：每层专注本层职责，上层不需要关心下层细节。

## 网络包的处理流程

**接收路径：**
```
网口收包 → process_layer2(buffer) → 摘MAC头，判断是否发给自己
         → process_layer3(buffer) → 摘IP头，判断是本地还是转发
         → process_tcp/udp(buffer) → 摘四层头，根据端口号交给应用
```

**发送路径：**
```
应用发请求 → send_tcp(buffer) → 加TCP头（端口号）
           → send_layer3(buffer) → 加IP头（源/目标IP）
           → send_layer2(buffer) → 加MAC头（源/目标MAC）
           → 网口发出
```

没有 `process_http(buffer)`——四层根据端口号将数据交给对应应用（如浏览器），应用层由应用自己处理。

## 核心原则

**只要在网络上跑的包，都是完整的。可以有下层没上层，绝对不可能有上层没下层。**

TCP 三次握手、重试——每次发包 IP 层和 MAC 层都完整运行一遍，不存在"只发 TCP 包不带 IP 和 MAC"的情况。

## 解惑：二层/三层/四层/七层设备

- **二层设备**（交换机）：只处理 MAC 头，决定丢弃、转发还是自留。包里的 HTTP/TCP/IP 内容它不关心，但包本身是完整的。
- **三层设备**（路由器）：摘 MAC 头后再摘 IP 头做路由决策。
- **四层 LB**：看 TCP/UDP 端口号做负载均衡。
- **七层 LB**：解析 HTTP 头做更精细的流量分发。

## 不恰当的比喻

"总经理握手时员工在干什么"这种比喻无法体现**层层封装**。正确的理解是：总经理说话→经理补充→组长补充→员工补充，内层包被外层包裹，像套娃一样。
