# 第18讲 DNS与HTTPDNS

## DNS 解析流程

```
客户端 → 本地DNS服务器（ISP提供）
           ↓ 无缓存
        根DNS服务器（13套，返回顶级域服务器地址）
           ↓
        .com 顶级域DNS服务器（返回权威DNS服务器地址）
           ↓
        163.com 权威DNS服务器（返回最终IP）
           ↓
        本地DNS缓存结果 → 返回客户端
```

DNS 服务器必须高可用、高并发、分布式。

## DNS 负载均衡

- **内部负载均衡**：应用配置域名而非 IP，DNS 轮询返回不同后端 IP。数据库切换 IP 只需改 DNS，不用改所有应用配置
- **全局负载均衡（GSLB）**：跨地域、跨运营商调度

**工作机制**：`object.yourcompany.com` CNAME 到 `object.vip.yourcompany.com`（GSLB）。第一层 GSLB 按运营商返回不同别名（如电信 → `object.dx.xxx`），第二层 GSLB 按地理位置返回最近的机房 IP。

## 传统 DNS 的问题

1. **域名缓存**：本地 DNS 缓存过期不更新，指向旧地址；运营商可能缓存页面替代真实网站
2. **域名转发**：A 运营商偷懒转发给 B 运营商解析，权威 DNS 误判运营商，导致跨运营商访问
3. **出口 NAT**：权威 DNS 无法通过 NAT 后的 IP 判断真实运营商
4. **更新延迟**：各 DNS 服务器 TTL 处理不一致，变更全网生效慢
5. **解析延迟**：递归查询多跳，可能超时

## HTTPDNS

不走传统 DNS，通过 HTTP 请求自己的 DNS 服务器集群：

```bash
curl http://106.2.xxx.xxx/d?dn=c.m.163.com
# 返回: {"dns":[{"host":"c.m.163.com","ips":["223.252.199.12"],"ttl":300}]}
```

### 优势

- 直接 HTTP 请求，无递归，速度快
- 客户端 SDK 自己维护缓存，过期/更新策略可控
- 服务器能准确获取客户端运营商和地理位置，精准调度
- 根据错误率、请求时间、服务器压力综合选择最优节点

### 缓存设计（Cache-Aside vs Refresh-Ahead）

- **同步更新（Cache-Aside）**：缓存未命中 → 请求 HTTPDNS → 更新缓存。实时性好，但并发过期时产生多个请求
- **异步更新（Refresh-Ahead）**：后台预加载即将过期的缓存。减少并发回源，但当前请求可能拿到旧数据

### 调度设计

客户端 SDK 上报各 IP 的网络请求质量（错误率、延迟），HTTPDNS 综合地理位置 + 质量数据 + 权重，排序返回最优 IP。不同运营商/WiFi SSID 分维度缓存。
