# 第14讲 流媒体协议

## 视频本质

视频 = 快速播放的连续图片序列。帧率 30fps，1024×768 分辨率下，未压缩视频每秒约 70MB，一分钟 4GB，无法直接存储和传输。

## 压缩原理

- **空间冗余**：相邻像素渐变，可隔几个存一个，中间用算法推算
- **时间冗余**：连续帧内容相似，可只存差异
- **视觉冗余**：人眼对某些细节不敏感，可丢失部分数据
- **编码冗余**：概率高的像素值用短编码（类似霍夫曼编码）

## 编码标准

- **ITU VCEG**：侧重传输（H.261、H.262、H.263、H.264、H.265）
- **ISO MPEG**：侧重存储（MPEG-1/2/4）
- **H.264/MPEG-4 AVC**：两者联合制定，当前主流

## 帧类型

- **I帧（关键帧）**：完整图片，可独立解码
- **P帧（前向预测）**：存与前一个 I/P 帧的差异
- **B帧（双向预测）**：存与前后帧的差异，压缩率最高

典型序列：I B B P B B P ...

## NALU 结构

编码后的视频流组织为 NALU（网络提取层单元）序列：
- `起始标识符 | NALU头（含类型） | Payload`
- 类型 `0x07` = SPS（序列参数集：图像尺寸等）
- 类型 `0x08` = PPS（图像参数集：类型、序列号等）
- 每个 I 帧前必须传输 SPS 和 PPS

## 直播流程

```
主播端（推流）→ 流媒体服务器（接流/转码）→ 分发网络 → 观众端（拉流/解码）
```

## RTMP 协议

基于 TCP，用于推流和拉流。

### 握手（六条消息）

C0/C1/C2（客户端） + S0/S1/S2（服务器），协商版本号和时间戳。

### 数据传输

- 将 NALU 去掉起始标识符后放入 Message
- Message 拆分为 Chunk 发送（低带宽下减少拥塞）
- 每个 Chunk 带 Message ID，接收端按 ID 组装

### 分发网络

中心层（转码、转发）+ 边缘层（就近服务用户）+ 智能负载均衡。

## HLS 协议

Apple 的流媒体方案，将视频切为小段（.ts 文件），通过 HTTP 传输。播放列表（.m3u8）记录各段的 URL。适合 CDN 分发。

## 防盗链

- **Referer 检查**：验证请求来源
- **时间戳签名**：URL 带加密签名和过期时间，CDN 端验证
