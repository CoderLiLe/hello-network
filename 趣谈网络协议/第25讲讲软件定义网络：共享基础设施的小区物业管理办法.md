# 第22讲 软件定义网络（SDN）

VLAN 和 Linux 网桥方式灵活性和隔离性不足，缺乏统一管理视图。

## SDN 核心特点

1. **控制与转发分离**：控制平面（集中控制器）负责决策，转发平面（网络设备）负责执行
2. **开放接口**：北向接口（控制器 → 应用层），南向接口（控制器 → 网络设备，如 OpenFlow）
3. **逻辑集中控制**：全局网络状态视图，统一优化

## OpenFlow 与 OpenvSwitch

OpenFlow 是 SDN 南向接口协议，OpenvSwitch（OVS）是虚拟交换机实现。

### 流表规则

每条规则包含：
- **匹配条件**：入端口、源/目标 MAC、源/目标 IP、源/目标端口、VLAN ID 等（覆盖 L1-L4）
- **执行动作**：转发到某端口、修改包头、丢弃等

内核态 Flow Table 保留高频规则做快速处理，未命中则 upcall 到用户态 vswitchd 进程全量匹配，匹配后下发回内核。

### OVS VLAN 实验

- **access port**：配置 tag，入口包打 tag，出口包去 tag
- **trunk port**：不配置 tag，配置 trunks，允许指定 VLAN ID 通过

### OVS 网卡绑定实验

bond_mode 三种：
- **active-backup**：主备
- **balance-slb**：按源 MAC 和 output VLAN 负载均衡
- **balance-tcp**：需 LACP 支持，按 L2/L3/L4 负载均衡

## SDN 在云计算中的应用

不用 OVS 时：每个用户需单独创建虚拟网桥和虚拟网卡。引入 OVS 后：
- 所有虚拟机放一个网桥 br0，不同 tag 即实现隔离
- 创建隔离网桥 br1 将物理网络和虚拟网络的 VLAN 解耦映射
- 物理 VLAN 规划和虚拟机 VLAN 各自独立，通过 `mod_vlan_vid` 映射转换

## SDN 控制器

如 OpenDaylight，可远程下发流表规则，展示全局拓扑图，灵活配置网络策略和负载均衡。
